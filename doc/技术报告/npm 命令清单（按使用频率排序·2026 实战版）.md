# 一、每日必用命令（高频）

## 1.1 npm install / npm i —— 安装依赖

**这是你每天打开项目终端后敲的第一个命令。**

### 基础用法

```bash
# 安装 package.json 中声明的所有依赖
npm install
# 简写
npm i
```

当你在 `desktop-app-template` 项目中执行 `npm install` 时，npm 会：

1. 读取 `../../package.json` 中的 `dependencies` 和 `devDependencies`
2. 检查 `package-lock.json` 是否存在
3. 下载所有依赖到 `node_modules`
4. 更新 `package-lock.json`（如有变化）

**npm 12 的重要变化**：`allowScripts` 现在**默认关闭**。依赖包的 `preinstall`、`install`、`postinstall` 脚本不会自动执行，除非明确授权。

> **💡 认知桥接**
>
> `npm install` 就像**从超市按购物清单（package.json）取货**。npm 12 之后，取货时不再自动打开包装盒里的"使用说明书脚本"（install scripts）——你得先确认这些脚本是安全的，再手动允许它们运行。

### 常用参数

| 参数 | 简写 | 说明 |
|------|------|------|
| `--save` | `-S` | 添加到 `dependencies`（**npm 5+ 默认行为**） |
| `--save-dev` | `-D` | 添加到 `devDependencies` |
| `--global` | `-g` | 全局安装 |
| `--save-exact` | `-E` | 精确版本（不加 `^`） |
| `--prefer-offline` | — | 优先使用本地缓存 |

### 实战场景

```bash
# 场景一：克隆项目后的第一步
git clone <repo-url>
cd desktop-app-template
npm install          # 安装所有依赖

# 场景二：添加生产依赖（运行时需要）
npm install recharts -S
# 等价于：npm install recharts --save

# 场景三：添加开发依赖（构建/测试时需要）
npm install @types/react -D
# 等价于：npm install @types/react --save-dev

# 场景四：安装指定版本
npm install react@18.3.1

# 场景五：全局安装工具
npm install -g typescript
npm install -g @vue/cli

# 场景六：优先使用缓存（网络不佳时）
npm install --prefer-offline
```

### 安装后发生了什么？

以 `desktop-app-template` 为例：

```
执行前：
desktop-app-template/
├── package.json        ← 声明了 react@^18.3.1, electron@^33.2.0 等
├── package-lock.json   ← 锁定精确版本
└── src/                ← 源代码

执行 npm install 后：
desktop-app-template/
├── package.json
├── package-lock.json   ← 可能更新
├── node_modules/       ← ←← 新生成！所有依赖下载到这里
│   ├── react/
│   ├── react-dom/
│   ├── electron/
│   ├── vite/
│   ├── typescript/
│   └── .bin/           ← 可执行文件（vite, electron, tsc 等）
└── src/
```

**项目能运行的直接原因**：`../../node_modules/.bin` 中的可执行文件（如 `vite`、`electron`）可以被 `npm run` 找到并执行。

## 1.2 npm run script —— 执行脚本

**这是你每天第二常用的命令。**

### 基础用法

```bash
npm run dev      # 执行 dev 脚本
npm run build    # 执行 build 脚本
```

`../../package.json` 中的 `scripts` 字段定义了可执行脚本：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "npm run build:main && npm run build:renderer",
    "build:main": "tsc -p tsconfig.main.json",
    "build:renderer": "vite build --config vite.renderer.config.ts",
    "start": "electron .",
    "package": "npm run build && electron-builder"
  }
}
```

### 工作原理

1. npm 读取 `../../package.json` 中的 `scripts` 字段
2. 将 `../../node_modules/.bin` 添加到 `PATH` 环境变量
3. 在项目根目录执行对应的 shell 命令

> **💡 认知桥接**
>
> `npm run` 就像**语音助手**——你说"运行 dev"，它就帮你执行预设好的命令序列。`../../node_modules/.bin` 被加入 PATH，相当于告诉系统"去这些工具箱里找工具"。

### 常用参数

```bash
# 查看所有可用脚本
npm run

# 传递参数给脚本（用 -- 分隔）
npm run test -- --coverage
# 实际执行：jest --coverage

# 在工作区中执行脚本（npm 7+）
npm run build --workspace=packages/shared
```

### 特殊脚本（可省略 run）

| 脚本名 | 执行方式 | 说明 |
|--------|---------|------|
| `start` | `npm start` | 启动应用 |
| `test` | `npm test` | 运行测试 |
| `stop` | `npm stop` | 停止应用 |
| `restart` | `npm restart` | 重启应用 |

```bash
# 以下两种写法等价
npm run start
npm start          # 可省略 run
```


`npm update` 遵循 `../../package.json` 中的版本范围：
- `^18.3.1` → 允许更新到 `18.3.x` 最新，不升级到 `19.x`

## 3.4 npm ci —— 干净安装（CI/CD 专用）

**专为持续集成环境设计的命令**。

```bash
npm ci
```

### npm ci vs npm install

| 对比维度 | `npm install` | `npm ci` |
|---------|--------------|----------|
| 是否依赖 `package-lock.json` | 否（没有则生成） | **是，必须存在** |
| 是否更新锁文件 | 可能更新 | **绝不更新** |
| 是否删除 `node_modules` | 否 | **是，全新安装** |
| 速度 | 较慢 | **更快** |
| 能否安装单个包 | 能 | **不能** |
| 适用场景 | 本地开发 | **CI/CD、生产构建** |

> **💡 认知桥接**
>
> `npm ci` 就像**工厂流水线的标准化装配**——严格按照图纸（package-lock.json）装配，不允许任何偏差。而 `npm install` 像**手工作坊**——可以根据情况灵活调整。

### 实战场景（CI/CD）

```yaml
# GitHub Actions 示例
- name: Install dependencies
  run: npm ci  # 更快、更可靠
- name: Build
  run: npm run build
```

## 4.3 npm cache —— 缓存管理

```bash
# 查看缓存目录

# 验证缓存完整性

# 清理缓存（强制）
```


### 何时需要清理缓存？

- `npm install` 报错且怀疑是缓存损坏
	- 从 npm v5 开始，其缓存机制具备了“**自我修复**”能力。缓存数据在存入和取出时都会被验证完整性，一旦发现损坏会自动重新获取。因此，官方认为除了释放磁盘空间外，**几乎没有必要清除缓存**。
- 磁盘空间不足
- 切换镜像源后包版本混乱

### `npm cache clean --force` 缺省和添加--force有什么差别？（npm5开始必须加--force才会执行，不加会报错）

`npm cache clean` 和 `npm cache clean --force` 的核心区别在于**删除的彻底程度**和**是否跳过安全检查**。

简单来说，`npm cache clean` 是一个“安全”的清理命令，而 `npm cache clean --force` 则是一个“强制”的清理命令。

两者的具体差异如下表所示：

| 对比维度           | `npm cache clean` (无 --force) | `npm cache clean --force`   |
| :------------- | :---------------------------- | :-------------------------- |
| **核心行为**       | **安全清理**                      | **强制清理**，会**删除缓存目录中的所有内容**  |
| **安全检查**       | **执行**，对缓存数据进行完整性校验后再决定是否删除   | **绕过**，跳过正常的安全检查机制，直接删除文件   |
| **适用场景**       | 日常维护，或想要安全地清理部分缓存时            | 缓存严重损坏导致安装失败等**应急处理**场景     |
| **主要风险**       | 低                             | **高**。可能导致后续安装变慢、CI/CD构建中断等 |
| **恢复成本**       | 低，可部分复用剩余缓存                   | **高**，所有依赖都需重新下载            |

#### 🚀 `--force` 强制删除的背后

从 npm v5 开始，其缓存机制具备了“**自我修复**”能力。缓存数据在存入和取出时都会被验证完整性，一旦发现损坏会自动重新获取。因此，官方认为除了释放磁盘空间外，**几乎没有必要清除缓存**。

所以，`npm cache clean` 命令现在默认**必须**带上 `--force` 参数才能执行。之所以保留这个“不安全”的选项，是为了应对极端的缓存损坏情况。

#### 💡 最佳实践建议

1.  **优先使用 `npm cache verify`**：遇到缓存相关问题时，先运行此命令。它会验证并修复缓存，是更安全的首选方案。
2.  **谨慎使用 `--force`**：仅在 `npm cache verify` 无效时，作为最后的应急手段使用。尤其是在 CI/CD 环境或网络受限时，需格外小心。
3.  **考虑其他方案**：如果问题仅涉及特定包，可使用 `npm cache delete <pkg-name>` 精准删除。在 CI 中，应配置如 `actions/cache` 这样的依赖缓存策略，而非依赖 npm 的本地缓存。


### `npm cache verify` 会自动修复？

**会的**。`npm cache verify` **具备自动修复损坏缓存的能力**。

这得益于 npm v5 及更高版本引入的**“自愈”（self-healing）缓存机制**。它的工作方式如下：

*   **自我修复是默认行为**：npm 在**写入**和**读取**缓存时都会进行完整性校验。一旦发现损坏，npm 会自动重新下载，因此你通常无需手动处理。
*   **`verify` 是“主动体检”**：这个命令会对整个缓存目录进行**离线验证**。它会强制检查所有文件的完整性，并**删除任何无效或损坏的数据**，这相当于一次主动的修复。
*   **附带“垃圾回收”**：除了修复损坏，`npm cache verify`还会**清理不再需要的缓存数据**，帮你释放磁盘空间。

#### 💡 最佳实践

1.  **首选 `npm cache verify`**：遇到缓存相关问题时（如`EINTEGRITY`校验失败），**优先执行此命令**。它是安全且有针对性的修复方案。
2.  **慎用 `npm cache clean --force`**：`verify`无法解决时再考虑。这会**删除所有缓存**，导致下次安装变慢。仅在`verify`无效或急需释放大量磁盘空间时使用。
3.  **日常可忽略**：得益于“自愈”机制，日常开发中你通常无需主动操作缓存。

## 5.4 npm dedupe —— 去重优化

**简化依赖树，减少重复包**。

```bash
# 去重优化
npm dedupe

# 查看重复（不执行去重）
npm find-dupes

# 安装时优先去重
npm install --prefer-dedupe
```

### 为什么需要 dedupe？

不同包可能依赖同一个库的不同版本：

```
去重前：
node_modules/
├── A/
│   └── node_modules/
│       └── lodash@4.17.20/
└── B/
    └── node_modules/
        └── lodash@4.17.21/

去重后（如果版本兼容）：
node_modules/
├── A/
├── B/
└── lodash@4.17.21/    ← 共享同一个版本
```


# 六、npm 12 新增安全命令

**npm 12 于 2026 年 7 月 8 日正式发布**，引入了一系列安全相关的破坏性变更。

## 6.1 npm approve-scripts —— 授权脚本执行

**允许特定依赖包执行安装脚本**。

```bash
# 查看所有待审批的脚本
npm approve-scripts --allow-scripts-pending

# 审批所有当前待审批的包
npm approve-scripts --all

# 审批特定包
npm approve-scripts sharp esbuild

# 审批时锁定版本（默认行为）
npm approve-scripts sharp
# 写入：{ "allowScripts": { "sharp@0.33.5": true } }

# 不锁定版本（允许未来版本自动继承授权）
npm approve-scripts sharp --no-allow-scripts-pin
```

**审批记录写入 `../../package.json`** ：

```json
{
  "allowScripts": {
    "sharp@0.33.5": true,
    "esbuild@0.24.0": true,
    "electron@33.2.0": true
  }
}
```

---

## 6.2 npm deny-scripts —— 拒绝脚本执行

**明确阻止特定包的脚本执行**。

```bash
# 阻止特定包执行脚本
npm deny-scripts node-sass
```

---

## 6.3 其他安全默认变更

| 变更 | 说明 | 绕过方式 |
|------|------|---------|
| `allowScripts: off` | 依赖生命周期脚本默认不执行 | `npm approve-scripts` |
| `--allow-git: none` | Git 依赖默认不解析 | `npm install --allow-git` |
| `--allow-remote: none` | 远程 URL 依赖默认不解析 | `npm install --allow-remote` |

### 从 npm 11 迁移到 12 的推荐步骤

```bash
# 1. 正常安装（会警告哪些包的脚本被跳过）
npm install

# 2. 查看待审批的包
npm approve-scripts --allow-scripts-pending

# 3. 审批所有当前包（快照当前状态）
npm approve-scripts --all

# 4. 提交审批记录
git add package.json && git commit -m "chore: snapshot current install-script allowlist"
```

### 常见包的脚本审批需求

| 包类型 | 示例 | 是否需要审批 |
|--------|------|-------------|
| 原生模块 | `sharp`, `bcrypt`, `canvas` | ✅ 需要（node-gyp 构建） |
| 浏览器自动化 | `cypress`, `playwright` | ✅ 需要（下载浏览器二进制） |
| Git Hooks | `husky` | ✅ 需要 |
| Electron | `electron` | ✅ 需要 |
| 纯 JS 工具 | `lodash`, `react` | ❌ 通常不需要 |

## 总结

这份命令清单按**实际使用频率**排序，覆盖了从每日必用到维护级命令的完整 spectrum。对于 `desktop-app-template` 项目：

**每日开发流程**：
```bash
npm install          # 早上第一件事（或克隆项目后）
npm run dev          # 启动开发服务器
npm run build        # 构建生产版本
npm start            # 启动 Electron 应用
npm test             # 运行测试
```

**依赖管理流程**：
```bash
npm install recharts -S    # 添加图表库
npm install @types/react -D # 添加类型定义
npm update                 # 定期更新依赖
npm outdated               # 检查哪些可以更新
npm audit                  # 安全检查
```

**npm 12 安全流程**：
```bash
npm install                # 安装（会警告跳过的脚本）
npm approve-scripts --allow-scripts-pending  # 查看待审批
npm approve-scripts --all  # 审批所有（快照当前状态）
```
