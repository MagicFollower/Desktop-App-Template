# 通用查询组件架构设计与实现

> 归档范围：将查询能力沉淀为可复用的核心基础组件，覆盖模糊查询、列表单选/多选、
> 多属性下拉（展示 name 取 id）、树形下拉，并与分页器联动。
> 适用版本：本次重构后。维护者：如新增字段类型，请按「扩展指引」操作。

## 一、需求

### 1.1 背景
人员管理、菜单管理等列表页都需要「查询区 + 分页」。此前 `QueryForm` 仅支持
`input` 与简单 `select`（值为 `string`），无法满足后续大量业务查询的共性诉求，
且分页器与查询条件割裂、需各页面重复拼装。

### 1.2 目标（用户原始诉求逐条映射）
| 编号 | 需求描述 | 落地能力 |
| --- | --- | --- |
| R1 | 部分条件模糊查询 | `type: 'input'` 文本模糊；`select/treeSelect` 的 `showSearch` 面板内按 label 模糊过滤 |
| R2 | 列表选择（单选、多选） | `type: 'select'` + `multiple` |
| R3 | 下拉框具有多属性，展示 name 取 id | `QueryOption` 允许附加任意字段；`optionRender` 自定义展示，值始终取 `value` |
| R4 | 树形下拉选择 | `type: 'treeSelect'`，支持单选/多选、展开收起、搜索 |
| R5 | 传入分页参数、与分页组件联动 | `QueryForm` 接收 `pagination` 配置，内部渲染 `Pagination`，与查询条件同属一个数据视图 |
| R6 | 组件足够通用，作为未来业务查询的核心基础件 | 字段配置驱动 + 类型分发，业务侧仅声明字段即可 |

### 1.3 约束
- 不引入额外第三方 UI 依赖（仅用 `@ant-design/icons` 与原生元素），保持深色主题一致。
- 兼容受控 / 非受控；`QueryForm` 刷新时不得卸载导致已输入条件丢失（沿用既有约定）。
- 编译遵循 `tsconfig` 的 `noUnusedLocals`，不得引入未使用声明。

## 二、设计

### 2.1 分层与组件关系
```
QueryForm（核心，字段配置驱动 + 分页联动）
├── Select        通用下拉（单/多选、模糊搜索、多属性）
├── TreeSelect    通用树形下拉（单/多选、展开、搜索）
├── Pagination    通用分页器（既有，复用）
└── hooks/useClickOutside    下拉/树面板「点击外部收起」共享钩子
```
设计原则：**控件与查询编排解耦**。`Select`/`TreeSelect` 是独立可用的表单控件，
既能被 `QueryForm` 编排，也能被未来的编辑弹窗、筛选器单独复用；`QueryForm` 只负责
「按字段类型分发渲染 + 值收集 + 动作（查询/重置）+ 分页联动」。

### 2.2 值模型
一次重构中最重要的决策是统一查询值类型：

```ts
export type QueryValue = string | string[]; // 文本/单选为 string，多选为 string[]
```

- 空值约定：文本/单选为 `''`，多选为 `[]`。`emptyValueOf(field)` 依据 `type`+`multiple` 推导，
  `buildInitialValues` 据此初始化，`handleReset` 复用同一函数保证「重置」语义一致。
- 业务侧读取时用 `asStr`/`asArr` 做窄化，避免 `string | string[]` 直接参与判断造成歧义。
  这一约束解决了历史上「用字段值猜测语义」的隐患，过滤逻辑对单选/多选显式分支。

### 2.3 字段配置类型（判别联合）
```ts
type QueryFieldConfig = QueryInputField | QuerySelectField | QueryTreeSelectField;
```
以 `type` 字段做可辨识联合，`renderControl` 内 `switch` 分发；新增类型只需：
① 扩展联合成员 → ② 在 `renderControl` 加一个 case → ③（如需要）在 `emptyValueOf` 补空值规则。

### 2.4 分页联动契约
```ts
interface QueryPaginationConfig {
  current; pageSize; total; pageSizeOptions?; showQuickJumper?; showSizeChanger?;
  onChange(page, pageSize): void;
}
```
- `total > 0` 才渲染分页行，避免空表出现无意义分页器。
- 联动语义由父级掌控：`onSearch` 触发时父级 `setPage(1)`；`pagination.onChange` 只更新页码/页长。
- 同时支持两类分页：客户端切片（如人员管理，onChange 仅改状态）与服务端取数（onChange 内再 reload），
  因 `QueryForm` 不关心数据如何产生，只透传 `current/pageSize/total`。

### 2.5 受控策略
`Select`/`TreeSelect` 均支持受控/非受控：优先用外部 `value`，否则维护内部 `inner` state，
`emit` 时「非受控才写内部 state、但始终回调 `onChange`」。`QueryForm` 以受控方式编排它们，
把值集中在自身 `values` state，故查询/重置的引用一致性可控（对外一律传浅拷贝）。

## 三、实现

### 3.1 交付文件
| 文件 | 动作 | 说明 |
| --- | --- | --- |
| `../../src/renderer/hooks/useClickOutside.ts` | 新增 | 点击外部收起，mousedown/touchstart 双绑定，`active` 关闭时不挂事件 |
| `../../src/renderer/components/Select/Select.tsx` / `.css` | 新增 | 单/多选、模糊搜索、多属性、可清除、多选标签 `maxTagCount` 折叠 |
| `../../src/renderer/components/TreeSelect/TreeSelect.tsx` / `.css` | 新增 | 树形下拉；搜索命中自动展开祖先；单/多选；标签折叠 |
| `../../src/renderer/components/QueryForm/QueryForm.tsx` / `.css` | 重构 | 字段配置驱动、类型分发、值模型升级、分页联动、loading 禁用 |
| `../../src/renderer/pages/System/UserManagement.tsx` / `.css` | 改造 | 演示模糊查询 + 多属性单选（角色）+ 多选（状态）+ 分页联动入 QueryForm |
| `../../src/renderer/pages/System/MenuManagement.tsx` | 改造 | 演示树形下拉（父级菜单）过滤，先按父裁剪子树再按名称/路径过滤 |

### 3.2 关键实现点
- **展示 name 取 id（R3）**：`roleOptions` 携带 `desc` 附加属性，`optionRender` 一行渲染
  名称 + 描述；`Select` 内部 `optionMap` 只以 `value` 回显/提交，保证「取 id」。
- **多选过滤正确性**：状态多选时 `statuses.length > 0 && !statuses.includes(...)` 才排除，
  空数组代表「不限」，与单选 `role` 的「空串代表不限」语义统一。
- **树搜索自动展开**：`TreeSelect` 在有关键词时用 `effectiveExpanded = collectAllKeys(displayTree)`
  临时展开全部命中祖先，不污染用户手动展开的 `expanded`。
- **子树裁剪**：`MenuManagement` 选父级后 `base = [findMenu(menus, parentId)]`，再走原
  `filterMenuTree`，保持「命中节点保留整棵子树」的既有行为。
- **点击外部与打开态**：`useClickOutside(rootRef, close, open)` 仅在打开时挂监听，
  `close` 内一并 `setKeyword('')`，下次打开恢复完整列表。

### 3.3 冗余清理
- 删除 `UserManagement` 页面级 `<Pagination>` 重复拼装与 import，改由 `QueryForm` 内聚渲染。
- 移除 `MenuManagement` 模块级 `queryFields` 常量（因依赖 `menus` 动态生成，移入组件 `useMemo`）。
- 两个页面对 `QueryForm` 的回调签名统一升级为 `Record<string, QueryValue>`，去除 `|| ''` 式散落判断。

## 四、验证
- `npx tsc --noEmit`：新增/改动文件 0 报错；仅剩项目原有的 6 个 `noUnusedLocals`
  告警（Dashboard/Login/useThemeStore），不在本次范围。
- `npm run build:renderer`：成功（`built in 4.31s`）。

## 五、扩展指引（给后来者）
1. **新增字段类型**（如日期区间 `dateRange`）：定义 `QueryDateRangeField` → 加入
   `QueryFieldConfig` 联合 → 在 `emptyValueOf` 补空值 → 在 `renderControl` 加 `case`。
2. **新页面接入**：声明 `queryFields: QueryFieldConfig[]` → `onSearch` 里 `setQuery(values)`
   并按 `asStr/asArr` 过滤 → 需要分页就传 `pagination`。
3. **独立复用控件**：`Select`/`TreeSelect` 可直接用于编辑弹窗，不依赖 `QueryForm`。

# 迭代二：查询页骨架与数据 Hook 沉淀

> 本次迭代解决三件事：①修复打开/新增触发的重复查询；②分页器移至数据列表下方并与查询、
> 网格组成完整区域、缩放时保持相对底部；③把「查询面板 + 数据 GRID + 分页器」连同其数据
> 生命周期一并通用化，供后续业务查询页直接复用。

## 一、需求
- **R7 单次加载**：打开人员管理、新增/删除后都只应触发 1 次查询。
- **R8 分页下移并固定底部**：分页器放在数据列表下方；查询面板 + 数据 GRID + 分页器为完整区域；
  整体缩放时分页保持在区域相对底部。
- **R9 区域通用化**：上述三段式与数据管理可被其它业务查询页「复制 + 小改」复用。

## 二、根因与修复（R7）
- **根因**：`main.tsx` 使用 `React.StrictMode`，开发环境下会对「挂载副作用」double-invoke。
  旧代码 `useEffect(() => reload(), [reload])` 无守卫，故进入页面即查询 2 次。
- **修复**：在 `useQueryTable` 内用 `initialized` ref 守卫首次加载，StrictMode 第二次进入时
  直接 return，保证只拉一次。查询/保存/删除各只显式调用一次 `reload()`，不再叠加。
- **附带**：`fetcher`/`filter` 用 ref 固化引用，令 `reload`/`search` 回调身份稳定，避免依赖抖动导致重取。

## 三、设计（R8/R9）
### 3.1 新增两段基础设施
| 名称 | 类型 | 职责 |
| --- | --- | --- |
| `components/QueryTableLayout` | 布局组件 | 纯展示三段式：顶部(标题+操作/查询面板) + 中部(数据区 flex:1 内滚动) + 底部(分页 flex-shrink:0)。撑满可用高度，缩放时分页恒在底部 |
| `hooks/useQueryTable` | 数据 Hook | 统一 `拉取→过滤→分页` 生命周期 + 单次加载守卫 + `search/reload/onPageChange`；`clientPagination=false` 支持树形等不分页 |

分层关系（迭代二后）：
```
业务页 = QueryTableLayout(展示) + useQueryTable(数据) + QueryForm(筛选)
QueryForm  ── 只负责条件收集与查询/重置（分页职责已移出）
QueryTableLayout ── 组合区：内嵌 Pagination 到数据区下方
```
**关键调整**：迭代一曾把分页塞进 `QueryForm`；本次依据「分页应在列表下方」的真实诉求，
将分页从 `QueryForm` 移除（连同其 `QueryPaginationConfig` 与相关 CSS），改由 `QueryTableLayout`
的 `pagination` 插槽渲染——职责重新单一，避免两套分页入口的冗余。

### 3.2 布局与「保持底部」实现要点
- 纵向链 `#root(100vh) → .app-shell → .app-shell-body → .app-layout → .app-main → .app-content(flex:1, overflow)` 已给出确定高度；
  `.query-table-layout { height:100%; display:flex; flex-direction:column }` 直接吃满。
- `.qt-body { flex:1; min-height:0; display:flex; flex-direction:column }`，其内
  `.qt-grid { flex:1; overflow:auto }` + `.qt-pagination { flex-shrink:0 }`。
- 数据少时网格 `flex:1` 占位，把分页顶到底；数据多时网格内部滚动，分页不跟着滚走；
  整体 zoom 缩放时 flex 结构不变，分页始终贴在区域底部——满足 R8。
- 表头吸顶：`.qt-grid thead th { position:sticky; top:0 }`。
- `plain` 逃生舱：树形等自带卡片样式的主体传 `plain`，去掉外层 `.qt-body` 卡片描边，避免双框。

## 四、实现与接入
- **人员管理**：`useQueryTable({ fetcher, filter: filterUsers })` + `QueryTableLayout`（title/extra/query/pagination），
  分页仅在 `total>0` 时渲染到数据区下方；删除越界页由 Hook 的 `currentPage` 收敛，移除页面手写回退逻辑。
- **菜单管理**：`useQueryTable({ fetcher, filter: filterMenusByQuery, clientPagination:false })`，
  用 `filtered` 作树数据；`QueryTableLayout plain` 承载拖拽提示 + 菜单表，无分页插槽。
- **冗余清理**：移除 `QueryForm` 的分页代码与样式；删除页面级重复的加载态门控、`setUsers/setMenus`、
  `table-toolbar/table-count` 死样式；过滤函数上提到模块作用域保证引用稳定。

## 五、复用指引（新业务查询页三步）
1. 模块作用域写纯 `filter(records, query)`（可选）。
2. `const t = useQueryTable({ fetcher, filter })` 取 `loading/rows/total/page/pageSize/search/reload/onPageChange`。
3. 用 `QueryTableLayout` 填 `title/extra/query=<QueryForm onSearch={t.search}/> / children=<表格> / pagination=<Pagination .../>`。

## 六、验证
- `npx tsc --noEmit`：改动文件 0 报错（仅剩项目原有 6 个 noUnusedLocals）。
- `npm run build:renderer`：成功（`built in 4.43s`）。
- 行为：进入页面/查询/新增/删除均各触发 1 次；分页贴于列表下方并随缩放保持在底部。

# 迭代三：布局去标题化与全站页面统一

> 本次迭代基于迭代二的三段式区域，进一步统一视觉与操作位置：①去掉与 TabBar 重复的页面
> 标题，查询面板顶到最上方；②把主操作（如「新增用户」）从标题栏右侧迁移到「查询面板与
> 数据列表之间」的左对齐工具栏；③让个人信息、菜单管理、文件管理、Redis、FTP 五个页面的
> 布局与人员管理保持一致。

## 一、需求
- **R10 去标题 + 操作归位**：移除列表页左上角重复的页面标题；查询面板置于区域最上方；
  主操作按钮放入查询与列表之间、左对齐的工具栏，布局更聚焦、更美观。
- **R11 全站一致**：个人信息、菜单管理、文件管理、Redis 查询、FTP 页面布局与人员管理一致
  （统一 24px 内边距、无重复标题、内容起于顶部、可复用同一骨架）。

## 二、设计：QueryTableLayout 插槽重构
迭代二的区域含 `title`+`extra` 头部与 `query/pagination`。本次依据 R10 调整插槽（迭代二正文作为历史快照保留，以其为准的差异以本表为准）：

| 插槽 | 迭代二 | 迭代三 | 说明 |
| --- | --- | --- | --- |
| `title` / `extra` | 顶部标题栏（左标题 / 右操作） | **移除** | 页面名由 TabBar 承载，区域不再重复 |
| `query` | 标题下方 | **区域最上方**（flex-shrink:0） | 查询面板顶到最上 |
| `toolbar` | —— | **新增**，查询与列表之间、左对齐（flex-shrink:0） | 承载「新增」等主操作 |
| `children`/`pagination` | 数据区 / 底部 | 不变 | flex:1 内滚 + 底部分页保持 R8 |

渲染顺序：`query → toolbar → body(grid + pagination)`。`.qt-toolbar` 用 `margin-bottom:4px`
下贴数据卡片，与区域 `gap:16px` 配合形成「操作条 + 表格」的视觉归属；`toolbar` 缺省则不占位。

## 三、实现与全站接入
- **人员管理**：去掉 `title`，`extra` → `toolbar`（新增用户按钮左对齐于查询与表格之间）。
- **菜单管理**：同样去 `title`、`extra` → `toolbar`；保留 `plain`（树形表格自带卡片）。
- **个人信息**：删除 `page-container` 内重复的 `page-header` 标题块，内容起于顶部，
  与列表页一致的 24px 内边距；表单页不适用查询+网格骨架，保持自身排版。
- **文件/Redis/FTP**：占位页迁移到 `QueryTableLayout` 骨架（File 的「上传文件」放入 `toolbar`），
  正文用 `page-placeholder` 在数据区内垂直居中，天然复用同一 padding 与高度链，功能落地即可
  直接填 `query`/`children`/`pagination`。

## 四、冗余清理
- `QueryTableLayout`：删除 `title/extra` 两个 props 与 `qt-header/qt-title/qt-extra` 样式，新增 `toolbar` 与 `qt-toolbar`。
- `pages.css`：`page-header` 已全站无引用，删除；新增通用 `page-placeholder`。
- 三个 Tools 页去除各自的 `page-container/page-header/h2/p` 结构，统一到同一骨架。

## 五、验证
- `npx tsc --noEmit`：改动文件 0 报错（仅剩项目原有 6 个 noUnusedLocals）。
- `npm run build:renderer`：成功（`built in 4.43s`）。
- 行为：人员/菜单页查询面板顶到最上、新增按钮左对齐于查询与列表之间；五个页面留白与标题风格一致；缩放时分页仍贴在列表下方底部。
