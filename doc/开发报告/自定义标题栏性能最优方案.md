# 自定义标题栏性能最优方案

## 问题回顾

### 初始需求
应用窗口缺少最小化、最大化、关闭按钮（`frame: false` + `titleBarStyle: 'hidden'`），用户无法控制窗口状态。

### 第一版方案的致命缺陷

**症状：** 界面全白，无任何内容渲染。

**根本原因（两个 bug）：**

1. **`SquareOutlined` 不存在于 @ant-design/icons**  
   验证结果：`SquareOutlined: undefined`  
   React 渲染 undefined 组件类型时抛出 "Element type is invalid" → **整棵组件树崩溃 → 白屏**。

2. **布局结构错误**  
   `.app-layout` 是 `display:flex`（默认横向），将 `<TitleBar />` 作为 `<Sidebar />` 的兄弟节点插入后，标题栏变成了横向 flex 行中的一个窄项，挤压整个布局。即使图标正常，UI 也会完全错乱。

### 附加设计缺陷

| 缺陷 | 影响 |
|------|------|
| TitleBar 放在 AppLayout 内 | 每次路由切换都随布局重新挂载，SVG/监听器反复创建销毁 |
| 登录页在 AppLayout 外 | `/login` 没有标题栏，`frame:false` 下用户无法关闭窗口，被"卡死" |
| 最大化状态用本地 useState | 与真实窗口状态脱钩（双击标题栏、Win+↑ 快捷键最大化后图标不变） |
| 依赖图标库引入 3 个图标 | 额外体积 + undefined 导出风险 |

---

## 最优方案设计

### 核心决策

**把 TitleBar 提升到 App 根层级（RouterProvider 之外），全局挂载一次。**

```
App.tsx
├── <div class="app-shell">              // #root 的子级，flex column
│   ├── <TitleBar />                     // 32px 固定，全局唯一，永不重挂
│   └── <div class="app-shell-body">     // flex:1, min-height:0
│       └── <RouterProvider />           // 路由内容（Login / AppLayout）
```

### 性能优化点

| 优化维度 | 做法 | 收益 |
|----------|------|------|
| **挂载位置** | App 根层级而非 AppLayout 内 | 路由切换时**永不卸载重挂**，SVG/事件监听器只创建一次 |
| **图标实现** | 内联 SVG 替代 @ant-design/icons | 消除 undefined 风险，减小 bundle 体积（VS Code 同款做法） |
| **窗口拖拽** | 原生 `-webkit-app-region: drag` | Chromium 合成器处理，**零 JS mousemove 开销** |
| **悬停效果** | 纯 CSS `:hover` | 无 re-render，GPU 合成 |
| **最大化图标** | 主进程真实事件驱动 | 仅在窗口实际最大化/还原时 re-render（罕见用户操作） |
| **覆盖范围** | 全局挂载 | 登录页自动获得窗口控件，不再"卡死" |
| **浏览器兼容** | 检测 electronAPI 存在性 | 浏览器开发模式下不渲染标题栏（浏览器自带 chrome） |

### 为什么这是性能最优？

1. **零重复挂载**：React Router 导航时 AppLayout 会重新渲染，但 TitleBar 在路由之外，始终存活。避免了每次路由切换时的：
   - SVG DOM 节点创建/销毁
   - IPC 监听器的 attach/detach
   - React 组件实例的 mount/unmount 生命周期

2. **零 JS 拖拽逻辑**：使用 Chromium 原生的 `-webkit-app-region: drag`，由 GPU 合成器直接处理窗口移动，不需要任何 JavaScript mousemove 事件监听和 state 更新。这是一个常见的性能陷阱——很多自定义标题栏用 JS 实现拖拽，每帧触发 re-render。

3. **零过渡动画开销**：Windows 原生标题栏按钮悬停是即时反馈，不加 transition。本方案遵循这一规范，避免不必要的 repaint。

4. **事件驱动的精确 re-render**：最大化状态只在主进程广播真实变化时才更新 React state，而不是靠轮询或假 toggle。窗口最大化是低频操作（用户主动触发），re-render 成本可忽略。

5. **内联 SVG 无组件间接层**：直接把 `<svg>` 写在 JSX 中，不抽成子组件。抽成组件会让每次 render 产生新的函数标识，可能触发子树 diff 异常。

### 1. 主进程：广播真实窗口状态 (`main.ts`)

```typescript
// 在 createWindow() 中，窗口创建后添加监听
const sendMaximizeState = () => {
  mainWindow?.webContents.send('window:maximized-changed', mainWindow.isMaximized());
};
mainWindow.on('maximize', sendMaximizeState);
mainWindow.on('unmaximize', sendMaximizeState);

// 新增 IPC handler 供渲染进程查询初始状态
ipcMain.handle('window:is-maximized', () => {
  return mainWindow?.isMaximized() ?? false;
});
```

**关键点：** 双击标题栏、Win+↑ 等系统操作不会经过渲染进程的点击 handler，必须靠主进程事件广播才能同步图标状态。

### 2. Preload：暴露 API (`preload.ts`)

```typescript
contextBridge.exposeInMainWorld('electronAPI', {
  // Window controls
  minimize: () => ipcRenderer.invoke('window:minimize'),
  maximize: () => ipcRenderer.invoke('window:maximize'),
  close: () => ipcRenderer.invoke('window:close'),
  isMaximized: () => ipcRenderer.invoke('window:is-maximized') as Promise<boolean>,
  onMaximizeChange: (callback: (maximized: boolean) => void) => {
    ipcRenderer.on('window:maximized-changed', (_event, maximized: boolean) => callback(maximized));
  },
  removeMaximizeChangeListener: () => {
    ipcRenderer.removeAllListeners('window:maximized-changed');
  },
  // ... 其他 API
});
```

### 3. 类型定义 (`electron.d.ts`)

```typescript
export interface ElectronAPI {
  minimize: () => Promise<void>;
  maximize: () => Promise<void>;
  close: () => Promise<void>;
  isMaximized: () => Promise<boolean>;
  onMaximizeChange: (callback: (maximized: boolean) => void) => void;
  removeMaximizeChangeListener: () => void;
  // ...
}
```

### 5. TitleBar 组件 (`TitleBar.tsx`)

```tsx
import { useEffect, useState } from 'react';
import './TitleBar.css';

function TitleBar() {
  const [maximized, setMaximized] = useState(false);
  const api = typeof window !== 'undefined' ? window.electronAPI : undefined;

  useEffect(() => {
    if (!api) return;
    // 挂载时读取一次真实状态
    api.isMaximized().then(setMaximized).catch(() => {});
    // 订阅主进程广播的状态变化
    api.onMaximizeChange(setMaximized);
    return () => api.removeMaximizeChangeListener();
  }, [api]);

  // 浏览器开发模式下没有 electronAPI，不渲染标题栏
  if (!api) return null;

  return (
    <div className="title-bar">
      <div className="title-bar-drag-region">Desktop App</div>
      <div className="window-controls">
        {/* 最小化按钮 — 内联 SVG */}
        <button type="button" className="window-control-btn" onClick={() => api.minimize()}>
          <svg width="10" height="10" viewBox="0 0 10 10" aria-hidden="true">
            <rect x="0" y="4.5" width="10" height="1" fill="currentColor" />
          </svg>
        </button>

        {/* 最大化/还原按钮 — 根据状态切换 SVG */}
        <button type="button" className="window-control-btn" onClick={() => api.maximize()}>
          {maximized ? (
            <svg width="10" height="10" viewBox="0 0 10 10" aria-hidden="true">
              <path d="M2.5 2.5v-2h7v7h-2M0.5 2.5h7v7h-7z" stroke="currentColor" strokeWidth="1" fill="none" />
            </svg>
          ) : (
            <svg width="10" height="10" viewBox="0 0 10 10" aria-hidden="true">
              <rect x="0.5" y="0.5" width="9" height="9" stroke="currentColor" strokeWidth="1" fill="none" />
            </svg>
          )}
        </button>

        {/* 关闭按钮 — Windows 风格红底 */}
        <button type="button" className="window-control-btn close" onClick={() => api.close()}>
          <svg width="10" height="10" viewBox="0 0 10 10" aria-hidden="true">
            <path d="M0.5 0.5L9.5 9.5M9.5 0.5L0.5 9.5" stroke="currentColor" strokeWidth="1" fill="none" />
          </svg>
        </button>
      </div>
    </div>
  );
}

export default TitleBar;
```

**关键设计：**
- SVG 直接内联在 JSX 中，不抽成子组件（避免新函数标识导致子树卸载重挂）
- 只有一个 `useState`，仅在窗口实际最大化/还原时触发 re-render（低频）
- 浏览器模式下返回 `null`，不渲染多余 DOM

## 验证结果

✅ **构建通过**：`npm run build` 无 TypeScript 错误  
✅ **登录页渲染**：浏览器访问 `http://localhost:5175/login` 显示完整 UI，无白屏  
✅ **标题栏可见**：Electron 模式下显示 32px 深色标题栏  
✅ **窗口控制**：三个按钮正常工作（最小化、最大化/还原、关闭）  
✅ **拖拽移动**：拖拽标题栏非按钮区域可移动窗口  
✅ **最大化同步**：双击标题栏或 Win+↑ 最大化后，图标正确切换为还原图标

## 性能对比

| 指标 | 第一版方案 | 最优方案 |
|------|-----------|---------|
| **挂载次数** | 每次路由切换重新挂载 | 应用生命周期内仅挂载一次 |
| **SVG 创建** | 每次挂载创建 3 个 SVG | 首次创建后复用 |
| **IPC 监听器** | 每次挂载 attach/detach | 首次 attach 后常驻 |
| **拖拽实现** | （未实现，若用 JS 则每帧 re-render） | Chromium 原生合成器，零 JS |
| **悬停 re-render** | （若有 transition 则触发） | 纯 CSS，零 re-render |
| **最大化图标准确性** | ❌ 假状态，与真实窗口脱钩 | ✅ 主进程事件驱动，100% 准确 |
| **登录页窗口控制** | ❌ 无按钮，用户卡死 | ✅ 有按钮，可正常关闭 |
| **Bundle 体积** | 引入 @ant-design/icons 部分模块 | 零额外依赖，内联 SVG |
| **undefined 崩溃风险** | ❌ SquareOutlined 不存在 | ✅ 无外部依赖，零风险 |
