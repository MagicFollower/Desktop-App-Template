# 数据库文件位置分析与说明

## 问题描述

用户发现以下两个位置存在数据库相关文件：
1. `C:\Users\X\AppData\Roaming\desktop-app-template\`
2. `C:\Users\X\Documents\Qoder\2026-09-01\382e4ffe\app-data.db`

疑问：这两个都是数据库文件吗？有什么作用？为什么会同时存在？

## 为什么会有"两个位置"的误解？

### 原因 1：历史代码遗留

在之前的迭代中，数据库路径配置经历过两次变更：

#### 第一阶段：使用 userData 目录（已废弃）
```typescript
// src/main/database.ts (旧代码)
const DB_PATH = join(app.getPath('userData'), 'app-data.db');
// 实际路径: C:\Users\X\AppData\Roaming\desktop-app-template\app-data.db
```

这个阶段数据库确实存在于 AppData/Roaming 目录。但后来因为以下原因被修改：
- AppData 是隐藏目录，用户难以查找和备份
- 打包后虽然可写，但开发模式下不够透明

#### 第二阶段：迁移到应用运行目录（当前方案）
```typescript
// src/main/database.ts (当前代码)
const DB_PATH = join(app.getAppPath(), 'app-data.db');
// 实际路径: C:\Users\X\Documents\Qoder\2026-09-01\382e4ffe\app-data.db
```

**迁移原因：**
- 项目根目录可见性强，便于用 SQLite 工具直接打开检查
- 备份简单（直接复制项目文件夹即可）
- 打包后数据库会放在可执行文件旁，同样易于管理

### 原因 2：文档未同步更新

`SQLite集成与FAQ.md` 仍保留着第一阶段的旧路径说明：

```markdown
Windows: C:\Users\<用户名>\AppData\Roaming\<应用名>\app-data.db
具体路径由 `app.getPath('userData')` 决定
```

这份文档创建于路径迁移之前，后续修改数据库路径时未同步更新文档，导致信息不一致。

### 原因 3：AppData 目录确实存在，但不是数据库

`C:\Users\X\AppData\Roaming\desktop-app-template\` 目录确实存在，包含：
- `Cache/` — Chromium 渲染缓存
- `Local Storage/` — localStorage 数据（浏览器模式下的备用存储）
- `Session Storage/` — sessionStorage 数据
- `Preferences` — Electron 偏好设置
- `Local State` — 本地状态文件

这些都是 **Electron/Chromium 运行时自动生成的缓存和配置**，不是应用的 SQLite 数据库。用户可能误以为整个 AppData 目录都是"数据库"。

## 数据库文件的真实作用

### 单一数据源架构

当前应用采用 **sql.js + IPC** 的单数据库架构：

```
┌─────────────────────────────────────┐
│   Renderer (React UI)               │
│   - 人员管理、菜单管理等页面          │
└──────────┬──────────────────────────┘
           │ IPC 调用 (menu:list, user:create...)
           ▼
┌─────────────────────────────────────┐
│   Main Process (Electron)           │
│   ┌───────────────────────────────┐ │
│   │  sql.js (WebAssembly SQLite)  │ │
│   │  ↓                            │ │
│   │  app-data.db (内存数据库)      │ │
│   │  ↓ 定期保存                    │ │
│   │  app-data.db (文件系统)        │ │
│   └───────────────────────────────┘ │
└─────────────────────────────────────┘
```

**关键点：**
- 只有一个 `app-data.db` 文件
- 使用 sql.js（WebAssembly 实现），无需 Visual Studio 编译工具
- 数据库在内存中运行，定期通过 `db.export()` 保存到文件
- 所有业务数据（用户、菜单、密码哈希）都存储在同一个数据库中

### 数据存储内容

| 表名 | 用途 | 示例数据 |
|------|------|----------|
| `users` | 用户基本信息 | admin, user, zhangsan, lisi, wangwu |
| `menus` | 菜单层级结构 | 仪表盘、系统管理、人员管理等 9 个菜单项 |
| `user_profiles` | 用户扩展资料 | 昵称、邮箱、手机、头像 |
| `passwords` | 密码哈希 | bcrypt 加密后的密码（admin123/user123） |

## 为什么 AppData 目录仍然存在？

即使数据库已迁移，AppData 目录仍然会被 Electron 自动创建，用于存储：

1. **Chromium 缓存**：渲染进程的资源缓存、GPU 缓存等
2. **localStorage/sessionStorage**：浏览器 API 的持久化存储
3. **Electron 偏好设置**：窗口位置、开发者工具状态等
4. **Cookie 和 IndexedDB**：如果应用使用了这些 Web API

**这些文件与应用的业务数据（app-data.db）完全无关**，是 Electron 框架层面的基础设施。

## 如何确认当前数据库位置？

### 方法 1：查看启动日志

启动应用时，控制台会打印数据库路径：

```
[DB] Database path: C:\Users\X\Documents\Qoder\2026-09-01\382e4ffe\app-data.db
[DB] app.getAppPath(): C:\Users\X\Documents\Qoder\2026-09-01\382e4ffe
[DB] app.getPath("userData"): C:\Users\X\AppData\Roaming\desktop-app-template
```

### 方法 2：检查文件时间戳

```bash
ls -lh app-data.db
# -rw-r--r-- 1 X 197121 72K Sep  6 12:20 app-data.db
```

最后修改时间与最近一次应用使用时间一致，说明这是活跃数据库。

### 方法 3：用 SQLite 工具验证

```bash
sqlite3 app-data.db ".tables"
# menus  passwords  user_profiles  users
```

能正常列出表结构，证明是有效的业务数据库。

## 清理建议

### 如果 AppData 中有旧的 app-data.db

如果在 `C:\Users\X\AppData\Roaming\desktop-app-template\` 目录下发现了 `app-data.db` 文件（本案例中未发现），可以安全删除：

```bash
rm "C:\Users\X\AppData\Roaming\desktop-app-template\app-data.db"
rm "C:\Users\X\AppData\Roaming\desktop-app-template\app-data.db-wal"
rm "C:\Users\X\AppData\Roaming\desktop-app-template\app-data.db-shm"
```

**注意：** 删除前请确认项目根目录的 `app-data.db` 已包含最新数据。

### 不要删除整个 AppData 目录

`C:\Users\X\AppData\Roaming\desktop-app-template\` 目录中的其他文件（Cache、Preferences 等）是 Electron 正常运行所需的，删除会导致：
- 首次启动变慢（需要重新生成缓存）
- 窗口位置和大小重置
- 开发者工具设置丢失

**只删除明确的旧数据库文件，保留其他 Electron 运行时文件。**
