# 开发体验与弹窗布局优化

本次迭代针对界面细节与调试体验做两项优化：弹窗位置、DevTools 打开方式。二者互不影响，各自独立。

---

## 一、新增/编辑弹窗整体偏下 → 上移并自适应

### 需求
新增/编辑用户等弹窗默认垂直居中，视觉重心偏低；表单较长时底部容易被裁切。希望弹窗整体上移，且**所有基于同一 `Modal` 组件的弹窗（新增/编辑用户、菜单编辑、删除确认、图标选择器、父级菜单选择器等）一并生效**，无需逐个调整。

### 设计
所有弹窗都渲染自同一个共享组件 `src/renderer/components/Modal/Modal.tsx` + `Modal.css`，因此只需改这一处样式即可全站统一。关键点：

- **遮罩层改为顶部对齐 + 上边距偏置**：`align-items: flex-start` + `padding: 8vh 16px 24px`，让弹窗靠上而非居中，避免"偏下"。
- **限制弹窗最大高度**：`.modal-container { max-height: 84vh }`，配合 flex 纵向布局，把溢出交给内部滚动。
- **仅内容区滚动**：`.modal-body { flex: 1 1 auto; min-height: 0; overflow-y: auto }`，表单过长时只有正文滚动，头部/底部按钮始终固定可见。
- **矮视口兜底**：`.modal-mask { overflow-y: auto }`，窗口很矮时整层可滚，防止底部被裁切。
- 入场动画相应改为 `translateY(-12px) → 0`（从上方淡入），与新的顶部定位一致。

### 影响面
`Modal.css` 是唯一被改文件；`Modal.tsx` 未动。凡是使用 `<Modal>` 的弹窗自动获得新布局，无需页面级改动。

## 二、Electron 默认自动打开 DevTools 的配置位置与切换方式

### 配置在哪里
自动打开 DevTools 的逻辑在 **`src/main/main.ts` 的 `createWindow()`** 内，开发模式分支（`process.env.NODE_ENV === 'development'`）中调用 `mainWindow.webContents.openDevTools()`。也就是说：**只有开发模式会默认打开**，生产模式不会。

### 之前的痛点
一旦手动关掉 DevTools，就只能重启服务（重新触发 `openDevTools()`）才能再次打开，很麻烦；且无法在不改代码的情况下关闭"自动打开"。

### 现在的处理
在 `main.ts` 做了两点增强：

1. **自动打开可关**：用环境变量 `OPEN_DEVTOOLS` 控制——
   ```powershell
   $env:OPEN_DEVTOOLS="false"; npm run start   # 启动时不再自动弹出 DevTools
   ```
   不设或设为非 `false` 时，仍保持"开发模式自动打开"的原行为。

2. **F12 随时切换**：注册 `before-input-event`，窗口内按 **F12** 即可开/关 DevTools（frameless 无菜单栏也能用），**无需重启服务**：
   ```typescript
   mainWindow.webContents.on('before-input-event', (_event, input) => {
     if (input.type !== 'keyDown' || input.key !== 'F12') return;
     const wc = mainWindow?.webContents;
     if (!wc) return;
     if (wc.isDevToolsOpened()) wc.closeDevTools();
     else wc.openDevTools();
   });
   ```
   另外 `Ctrl+Shift+I` 由 Electron 默认菜单同样可切换。

### 回答常见疑问
- **"关闭 DevTools 后只能重启服务再打开吗？"** —— 不再需要。按 **F12**（或 `Ctrl+Shift+I`）即可重新打开。
- **"能默认不弹吗？"** —— 能。设 `OPEN_DEVTOOLS=false` 后再启动。
