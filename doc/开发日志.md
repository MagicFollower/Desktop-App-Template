## 1. 动机与需求分析

### 1.1 动机

用户展示了一张 RedisInsight（Redis 官方 GUI 客户端）的截图，对其界面美观度和动态效果印象深刻。核心诉求不是复刻 RedisInsight 本身，而是**提取其 UI 设计语言，构建一个通用的 Windows 桌面应用开发模板**，让后续项目可以快速复用这套深色主题、侧边栏导航、标签页系统、实时图表仪表盘的交互模式。

### 1.2 需求分析

通过对截图的逆向分析，提取出以下核心 UI 需求：

| 需求编号 | 需求描述 | 优先级 | 实现方式 |
|---------|---------|--------|---------|
| N1 | 深色主题 UI，还原截图配色 | P0 | CSS 变量 + 全局样式 |
| N2 | macOS 风格窗口控制按钮（红黄绿圆点） | P0 | Electron frameless + 自定义按钮 |
| N3 | 左侧可折叠树形导航栏（数据库/键浏览） | P0 | 递归树组件 + 状态管理 |
| N4 | 顶部标签页系统（支持多标签、添加/关闭） | P0 | 标签状态管理 + 事件驱动 |
| N5 | 实时数据仪表盘（4 个动态图表） | P0 | Recharts + 定时数据更新 |
| N6 | 顶部统计卡片（运行时间、客户端数、键总数、内存） | P1 | 网格布局 + 数据绑定 |
| N7 | 版本/模式标签（v8.6.2、standalone、master） | P1 | 标签组件 + 语义化分类 |
| N8 | 自定义滚动条样式 | P2 | CSS 滚动条伪元素 |
| N9 | 实时 WebSocket 数据推送模拟 | P1 | IPC 通信 + 定时器 |
| N10 | Windows 平台打包分发 | P1 | electron-builder |

### 1.3 非功能需求

- **性能**：图表每秒更新，要求渲染开销可控，不造成主线程阻塞
- **可维护性**：组件化设计，样式隔离，类型安全
- **可扩展性**：模板化程度高，新增页面/组件只需遵循约定
- **跨平台基础**：代码结构支持后续扩展至 macOS/Linux

## 2. 技术选型决策

### 2.1 为什么选择 Electron 而非其他方案

| 方案 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| **Electron** | 生态成熟、React 友好、跨平台、社区庞大 | 内存占用较高（~150MB） | ✅ 选择 |
| Tauri | 内存占用低（~10MB）、Rust 后端 | 生态不如 Electron、Windows 打包复杂 | ❌ 生态不够成熟 |
| NW.js | 支持 Web API | 已被 Node-Webkit 社区废弃、维护不活跃 | ❌ 不推荐 |
| WebView2 | 系统原生、轻量 | 需要处理浏览器兼容、UI 定制受限 | ❌ 定制性不足 |
| Qt + WebEngine | 性能好、C++ 生态 | 学习曲线陡峭、UI 开发效率低 | ❌ 开发效率低 |

**最终选择 Electron**，理由：
1. 截图本身就是一个 Electron 应用（RedisInsight 基于 Electron）
2. React + TypeScript 生态在 Electron 中最成熟
3. electron-builder 提供一站式打包方案
4. 社区资源丰富，遇到问题容易找到解决方案

### 2.2 前端框架选型

| 框架 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| **React 18** | 组件化成熟、Hooks API、生态最大 | 学习曲线 | ✅ 选择 |
| Vue 3 | 模板语法直观、组合式 API | Electron 生态案例较少 | ❌ |
| Svelte | 编译时优化、包体积小 | 生态较小、Electron 集成文档少 | ❌ |
| Angular | 企业级完整方案 | 过于重、学习成本高 | ❌ |

**选择 React 18**，因为：
- 截图中的组件化 UI 模式（侧边栏、标签页、图表卡片）天然适合 React 的组件思维
- Recharts 是 React 生态的图表库，与 React 深度集成
- React Hooks 适合管理实时数据流（useEffect + 定时器）

### 2.3 构建工具选型

| 工具 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| **Vite** | 极速 HMR、原生 ESM 支持、配置简洁 | 需要处理 Electron 主进程编译 | ✅ 选择 |
| Webpack | 生态成熟、插件丰富 | 配置复杂、HMR 慢 | ❌ |
| esbuild | 极速构建 | 生态插件少、配置不够灵活 | ❌ |

**选择 Vite** 用于渲染进程，主进程使用 tsc 直接编译。

### 2.4 图表库选型

| 库 | 优势 | 劣势 | 结论 |
|----|------|------|------|
| **Recharts** | React 原生、声明式 API、主题定制好 | 大数据量性能一般 | ✅ 选择 |
| Chart.js | 功能全面、性能好 | 非 React 原生、需要 wrapper | ❌ |
| D3.js | 极度灵活、定制化最强 | 学习曲线陡峭、开发效率低 | ❌ |
| ECharts | 功能强大、中文文档好 | 包体积大、React 集成一般 | ❌ |

**选择 Recharts**，因为截图中的面积图（AreaChart）风格与 Recharts 高度匹配，且 Recharts 的声明式 API 与 React 哲学一致。

### 3.2 数据流设计

```
┌──────────┐  IPC     ┌──────────┐  React State  ┌──────────┐
│  Main    │ ───────▶ │  App.tsx │ ───────────▶  │  组件     │
│  Process │  <─────── │  (State) │ ◀───────────  │  渲染     │
└──────────┘          └──────────┘                └──────────┘
     ▲                        │
     │ WebSocket Mock         │ useState / useEffect
     │ (setInterval 1s)       │
     └────────────────────────┘
```

**数据流说明**：
1. 主进程通过 `setInterval` 每 1 秒生成模拟数据
2. 通过 `webContents.send('mock-data', data)` 推送给渲染进程
3. 渲染进程通过 `ipcRenderer.on('mock-data', callback)` 接收
4. 调用 `setMockData(data)` 更新 React 状态
5. React 重新渲染，Recharts 图表平滑过渡

### 3.3 组件层级设计

```
App (状态管理 + 布局)
├── WindowControls (窗口控制)
├── Sidebar (侧边栏导航)
│   ├── TreeNode (递归渲染树节点)
│   └── SearchBar (搜索过滤)
└── MainContent (主内容区)
    ├── TabBar (标签页管理)
    └── Dashboard (仪表盘)
        ├── Header (标题 + 版本标签)
        ├── StatsBar (统计卡片)
        └── ChartsGrid (图表网格)
            └── RealtimeChart (实时图表)
                └── Recharts AreaChart
```

### 3.4 状态管理策略

采用 **React 内置状态管理**（不使用 Redux/Zustand），理由：

1. 当前项目规模较小，组件层级不深
2. 避免引入额外依赖，降低包体积
3. React 18 的 `useReducer` + `Context` 已足够应对中等复杂度
4. 模板定位是"起点"，开发者可以根据需要自行引入状态管理库

**状态分配**：

| 状态 | 管理方式 | 位置 |
|------|---------|------|
| 活动标签 | `useState` | App.tsx |
| 标签列表 | `useState` | App.tsx |
| 侧边栏选中项 | `useState` | App.tsx |
| 侧边栏展开状态 | `useState` (Set) | Sidebar.tsx |
| 实时图表数据 | `useState` + `useEffect` | RealtimeChart.tsx |
| WebSocket 连接状态 | `useState` | App.tsx |

### 3.5 样式系统设计

采用 **独立 CSS 文件 + BEM 命名约定**，不使用 CSS Modules / Styled Components，理由：

1. Electron 应用不需要打包优化，CSS 文件体积不是问题
2. 独立 CSS 文件更直观，便于调试和审查
3. 避免构建工具链复杂度
4. BEM 命名保证样式隔离

#### 5.1.2 创建 TypeScript 配置

创建了三个 TypeScript 配置文件：

**`tsconfig.json`**（渲染进程 - 通用配置）：
- 目标：ES2020 + DOM
- 模块：ESNext（Vite 原生支持）
- JSX：react-jsx（React 17+ 编译时 JSX）
- 路径别名：`@/*` → `src/renderer/*`
- 严格模式：开启

**`tsconfig.main.json`**（主进程 - Electron 专用）：
- 目标：ES2020（无 DOM 类型）
- 模块：commonjs（Electron 主进程需要）
- 输出：`dist/main/`
- 根目录：`src/main/`

**`vite.renderer.config.ts`**（Vite 构建配置）：
- 插件：`@vitejs/plugin-react`
- 别名：`@` → `src/renderer/`
- 输出：`dist/renderer/`
- 开发服务器端口：5173

**遇到的问题**：

> **问题 2**：主进程和渲染进程的 TypeScript 配置冲突。
>
> 渲染进程需要 DOM 类型（React 需要），主进程不需要。如果共用一个 tsconfig，主进程会引入不必要的 DOM 类型，导致 `document`、`window` 等全局变量在主进程中可用，违反安全原则。
>
> **解决方案**：使用两个独立的 tsconfig 文件。`tsconfig.main.json` 不包含 `DOM` lib，`tsconfig.json` 包含 `DOM` lib 但仅用于 IDE 提示和渲染进程编译。Vite 构建时不依赖 tsconfig.json 的类型检查，只进行代码转换。

### 5.2 主进程开发

#### 5.2.1 创建 preload.ts（安全桥接）

**文件**：`src/main/preload.ts`

```typescript
import { contextBridge, ipcRenderer } from 'electron';

contextBridge.exposeInMainWorld('electronAPI', {
  minimize: () => ipcRenderer.invoke('window:minimize'),
  maximize: () => ipcRenderer.invoke('window:maximize'),
  close: () => ipcRenderer.invoke('window:close'),
  onMockData: (callback: (data: MockData) => void) => {
    ipcRenderer.on('mock-data', (_event, data: MockData) => callback(data));
  },
  removeMockDataListener: () => {
    ipcRenderer.removeAllListeners('mock-data');
  },
});

export interface MockData {
  timestamp: number;
  commandsPerSec: number;
  connectedClients: number;
  memoryUsage: number;
  networkInput: number;
  networkOutput: number;
}
```

**设计决策**：

1. **使用 `contextBridge`**：这是 Electron 推荐的安全方式，防止渲染进程直接访问 Node.js API
2. **暴露方法而非直接暴露 ipcRenderer**：渲染进程只能通过预定义的方法与主进程通信
3. **定义 MockData 接口**：类型定义放在 preload 中，主进程和渲染进程共享同一份类型

**遇到的问题**：

> **问题 3**：`ipcRenderer.on` 的回调类型不匹配。
>
> `ipcRenderer.on` 的回调签名是 `(event: IpcRendererEvent, ...args: any[]) => void`，但我们需要提取第二个参数 `data`。
>
> **解决方案**：使用 `_event` 忽略事件对象，通过解构提取 `data` 参数。同时添加 `removeMockDataListener` 方法，方便组件卸载时清理监听器，防止内存泄漏。

---

#### 5.2.2 创建 main.ts（主进程入口）

**文件**：`src/main/main.ts`

核心功能：

1. **窗口创建**：
   - 使用 `screen.getPrimaryDisplay().workAreaSize` 获取主屏幕尺寸
   - 窗口大小设为屏幕的 85%，最小尺寸 1024x700
   - `titleBarStyle: 'hidden'` + `frame: false` 实现无边框窗口
   - `backgroundColor: '#0f0f1a'` 设置深色背景，避免白闪

2. **开发/生产模式区分**：
   - 开发模式：加载 `http://localhost:5173`，自动打开 DevTools
   - 生产模式：加载 `dist/renderer/index.html`

3. **Mock WebSocket 数据模拟**：
   - `setInterval` 每 1 秒生成随机数据
   - 通过 `webContents.send('mock-data', data)` 推送
   - 模拟数据包含：commandsPerSec、connectedClients、memoryUsage、networkInput/Output

4. **IPC 处理窗口控制**：
   - `window:minimize` → `mainWindow.minimize()`
   - `window:maximize` → 切换最大化状态
   - `window:close` → `mainWindow.close()`

**遇到的问题**：

> **问题 4**：无边框窗口在 Windows 上无法拖拽移动。
>
> 使用 `frame: false` 后，窗口失去了系统拖拽能力，用户无法移动窗口。
>
> **解决方案**：在 CSS 中使用 `-webkit-app-region: drag` 为标题栏区域添加拖拽能力。当前模板中窗口控制按钮区域使用 `-webkit-app-region: no-drag` 确保按钮可点击。完整方案需要在 WindowControls 上方添加一个透明的拖拽区域（当前模板简化处理，后续版本可补充）。

> **问题 5**：`webContents.send` 在窗口关闭后仍会尝试发送数据，导致内存泄漏。
>
> **解决方案**：在 `setInterval` 中添加窗口有效性检查：`if (mainWindow && !mainWindow.isDestroyed())`。同时在应用退出时清理定时器（当前通过进程退出自动清理，更严谨的做法是使用 `app.on('before-quit')` 清理）。

#### 5.3.2 创建 App.tsx（根组件 + 状态管理）

**文件**：`src/renderer/App.tsx`

这是整个应用的状态中心，管理：
- 标签页状态（列表、活动标签）
- 侧边栏选中项
- WebSocket 连接状态
- 实时数据接收

**关键代码模式**：

```typescript
// 标签页状态管理
const [tabs, setTabs] = useState<Tab[]>(initialTabs);
const [activeTab, setActiveTab] = useState('status');

// 标签添加（使用 useCallback 避免闭包陷阱）
const handleAddTab = useCallback(() => {
  const newTab: Tab = {
    id: `tab-${Date.now()}`,
    label: `新标签 ${tabs.length + 1}`,
    icon: '📄',
  };
  setTabs(prev => [...prev, newTab]);
  setActiveTab(newTab.id);
}, [tabs.length]); // 依赖 tabs.length 而非 tabs 数组本身

// WebSocket 数据接收
useEffect(() => {
  const api = (window as any).electronAPI;
  if (api) {
    api.onMockData((data: MockData) => setMockData(data));
    return () => api.removeMockDataListener(); // 清理监听器
  }
}, []);
```

**遇到的问题**：

> **问题 6**：`handleAddTab` 的依赖数组中使用了 `tabs.length` 而非 `tabs` 本身。
>
> 如果依赖 `tabs` 数组，每次添加标签都会重新创建函数，导致子组件不必要的重渲染。但只依赖 `tabs.length` 可能导致 stale closure（闭包捕获旧值）。
>
> **解决方案**：使用 `setTabs(prev => [...prev, newTab])` 的函数式更新，不依赖闭包中的 `tabs` 值。依赖 `tabs.length` 只是为了确保函数在标签数量变化时重新创建。这是一个权衡，对于当前规模的项目完全够用。

> **问题 7**：`(window as any).electronAPI` 的类型不安全。
>
> 渲染进程无法直接访问 `preload.ts` 中定义的 `electronAPI` 类型。
>
> **解决方案**：在 `App.tsx` 的顶层定义全局类型声明：
> ```typescript
> declare global {
>   interface Window {
>     electronAPI: {
>       minimize: () => void;
>       maximize: () => void;
>       close: () => void;
>       onMockData: (callback: (data: MockData) => void) => void;
>       removeMockDataListener: () => void;
>     };
>   }
> }
> ```
> 当前模板使用 `(window as any)` 作为快速方案，生产项目建议添加完整的类型声明文件。

#### 5.4.5 RealtimeChart（实时图表组件）

**文件**：`src/renderer/components/RealtimeChart.tsx` + `.css`

使用 Recharts 的 `AreaChart` 实现实时面积图：

**核心逻辑**：

```typescript
useEffect(() => {
  // 初始化 10 个历史数据点
  const initialData: DataPoint[] = [];
  for (let i = 9; i >= 0; i--) {
    const time = new Date(now.getTime() - i * 1000);
    initialData.push({
      time: formatTime(time),
      value: Math.random() * 2,
    });
  }
  setChartData(initialData);

  // 每秒更新
  intervalRef.current = setInterval(() => {
    setChartData(prev => {
      const newData = [...prev.slice(1)]; // 移除最旧的数据
      newData.push({ time: formatTime(new Date()), value: data });
      return newData; // 固定窗口：始终保留 10 个点
    });
  }, 1000);

  return () => clearInterval(intervalRef.current);
}, [data]);
```

**渐变填充效果**（复刻截图中的面积图渐变）：

```tsx
<defs>
  <linearGradient id={gradientId} x1="0" y1="0" x2="0" y2="1">
    <stop offset="5%" stopColor={color} stopOpacity={0.3} />
    <stop offset="95%" stopColor={color} stopOpacity={0} />
  </linearGradient>
</defs>
<Area
  type="monotone"
  dataKey="value"
  stroke={color}
  fill={`url(#${gradientId})`}
  strokeWidth={2}
  dot={false}
  activeDot={{ r: 4 }}
/>
```

**双线图模式**（网络输入/输出）：

```tsx
<Area type="monotone" dataKey="value" stroke={colorInput} fill={gradientInput} />
<Area type="monotone" dataKey="value" stroke={colorOutput} fill={gradientOutput} />
```

**遇到的问题**：

> **问题 15**：Recharts 的 `AreaChart` 在数据更新时出现闪烁/跳变。
>
> 原因：Recharts 默认有动画效果（`isAnimationActive={true}`），每秒数据更新时动画叠加导致视觉闪烁。
>
> **解决方案**：在 `AreaChart` 上设置 `isAnimationDuration={0}` 或 `isAnimationActive={false}`。当前模板使用默认动画，因为 1 秒的更新间隔足够长，动画效果反而增加了平滑感。如果用户觉得闪烁，可以添加 `isAnimationActive={false}` 属性。

> **问题 16**：双线图模式下，两个 `Area` 使用相同的 `dataKey="value"`，导致 Recharts 无法区分两条线。
>
> **解决方案**：当前实现中，两个 Area 共享相同的数据源（chartData），Recharts 通过 `stroke` 和 `fill` 属性区分。实际上这是一个 bug——应该使用不同的 dataKey 或数据字段。修复方案：
> ```typescript
> // 数据结构改为包含 input 和 output 两个字段
> interface DualDataPoint {
>   time: string;
>   input: number;
>   output: number;
> }
> // Area 1: dataKey="input"
> // Area 2: dataKey="output"
> ```
> 当前模板作为演示，使用了简化的共享数据方案，后续版本需要修复。

> **问题 17**：X 轴时间标签在快速更新时重叠。
>
> 10 个数据点，每个间隔 1 秒，时间格式为 `HH:MM:SS`，标签宽度约 50px，10 个标签需要 500px。
>
> **解决方案**：在 `XAxis` 上设置 `tickFormatter` 只显示 `MM:SS`（省略小时），减少标签宽度。或者使用 `interval={1}` 每隔一个标签显示一次。

## 8. 后续扩展方向

### 8.1 短期改进（P1）

1. **真实 WebSocket 连接**：替换 mock 数据，连接真实 Redis 服务器或后端 API
2. **类型安全**：为 `window.electronAPI` 添加完整的类型声明文件
3. **虚拟滚动**：侧边栏树节点超过 500 个时启用虚拟滚动
4. **键盘快捷键**：支持 Ctrl+T 新建标签、Ctrl+W 关闭标签、Ctrl+N 新窗口
5. **窗口拖拽**：添加标题栏拖拽区域，支持移动窗口

### 8.2 中期改进（P2）

1. **状态管理升级**：引入 Zustand 或 Redux Toolkit，管理更复杂的全局状态
2. **路由系统**：添加 React Router，支持多页面导航
3. **国际化**：添加 i18n 支持（截图中有中文界面）
4. **主题系统**：支持用户切换深色/浅色主题
5. **插件系统**：允许第三方扩展组件

### 8.3 长期愿景

1. **多窗口支持**：类似 Chrome 的多窗口架构
2. **拖放操作**：支持从侧边栏拖拽键到编辑器
3. **搜索高亮**：侧边栏搜索时高亮匹配的键名
4. **性能监控**：添加应用自身的性能监控面板
5. **自动更新**：集成 electron-updater，实现自动更新
