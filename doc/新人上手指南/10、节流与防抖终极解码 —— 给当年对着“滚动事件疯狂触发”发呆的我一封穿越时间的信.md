## 第一章：先解决你最大的困惑 —— 它们是什么？

### 1.1 脑内翻译官（用生活场景秒懂）

想象你在**按电梯关门按钮**：

- **防抖（Debounce）** = **“等没人按了再关门”**
  - 你连续按了 5 次关门按钮，电梯不会每次响应。
  - 它等你**停止按了 3 秒后**，才开始关门。
  - 如果你在 3 秒内又按了一下，计时器重置，重新等 3 秒。
  - **应用场景：** 搜索框输入、窗口 resize、表单提交按钮防重复点击。

- **节流（Throttle）** = **“每 3 秒只能按一次”**
  - 你疯狂按关门按钮，电梯每 3 秒只响应一次。
  - 你按 100 次，它也只执行 33 次（100 / 3）。
  - **应用场景：** 滚动加载、游戏射击、鼠标移动跟踪。

> **一句话总结：**
> - **防抖**：**“我在等你停下来”** —— 连续触发时只执行最后一次。
> - **节流**：**“我在限制你的频率”** —— 连续触发时按固定间隔执行。


### 1.2 可视化对比（一看就懂）

```
时间轴（每秒一个刻度）：0-----1-----2-----3-----4-----5-----6-----7-----8-----
用户触发事件：         x--x--x-----x--------x-----x--x--x-----x--------x-----
                       ↑  ↑  ↑     ↑        ↑     ↑  ↑  ↑     ↑        ↑

【防抖（延迟 2 秒）】
等待 2 秒：            --------执行--------------
                                    ↑  ↑  ↑     ↑        ↑     ↑  ↑  ↑     ↑
                      等到停下来 2 秒后→        --------------------执行------
                                                            等到停下来 2 秒后→
结果：                            ✅                            ✅
（只执行了 2 次）

【节流（间隔 2 秒）】
每 2 秒执行一次：      ✅         ✅         ✅         ✅         ✅
结果：                 ↑          ↑          ↑          ↑          ↑
（固定频率执行了 5 次）
```

## 第二章：从零实现 —— 手写防抖

理解了概念，我们来看看它们到底是怎么实现的。

### 2.1 基础防抖（最简版本）

```tsx
// ============================================
// 防抖核心原理：利用闭包保存 timer
// ============================================
function debounce<T extends (...args: any[]) => any>(
  fn: T,
  delay: number
): (...args: Parameters<T>) => void {
  // ★ 闭包：保存定时器 ID
  let timer: NodeJS.Timeout | null = null;

  // 返回的是“防抖化”后的函数
  return function(this: any, ...args: Parameters<T>) {
    // 每次调用：清除之前的定时器
    if (timer) {
      clearTimeout(timer);
    }
    // 重新设置定时器：延迟 delay 毫秒后执行
    timer = setTimeout(() => {
      fn.apply(this, args);
      timer = null;
    }, delay);
  };
}

// 使用场景：搜索框输入
const searchInput = document.getElementById('search') as HTMLInputElement;
const handleSearch = debounce((keyword: string) => {
  console.log('🔍 搜索:', keyword);
  // 发起 API 请求
}, 500);

searchInput.addEventListener('input', (e) => {
  handleSearch((e.target as HTMLInputElement).value);
});
```

**运行流程：**
1. 用户输入 'a' → 设置定时器（500ms 后执行）
2. 用户输入 'ab'（300ms 后）→ 清除旧定时器，重新设置
3. 用户输入 'abc'（200ms 后）→ 清除旧定时器，重新设置
4. 用户停止输入 → 等待 500ms → 执行搜索 'abc'

> **💡 核心洞察：** 防抖的精髓就是 **“清除-重设-清除-重设”** ，直到用户停止触发。

### 2.2 进阶防抖：立即执行版（“先执行再等待”）

有时候我们希望**第一次触发立即执行**，后续的连续触发才做防抖。比如“提交表单”按钮，第一次点击立即提交，后续点击防抖。

```tsx
// ============================================
// 防抖（立即执行版）：第一次立即执行，后续防抖
// ============================================
function debounceImmediate<T extends (...args: any[]) => any>(
  fn: T,
  delay: number
): (...args: Parameters<T>) => void {
  let timer: NodeJS.Timeout | null = null;
  let isFirstCall = true; // 标记是否是第一次调用

  return function(this: any, ...args: Parameters<T>) {
    // 第一次调用：立即执行
    if (isFirstCall) {
      fn.apply(this, args);
      isFirstCall = false;
      // 设置定时器，delay 后重置标记
      timer = setTimeout(() => {
        isFirstCall = true;
        timer = null;
      }, delay);
      return;
    }

    // 后续调用：防抖逻辑
    if (timer) {
      clearTimeout(timer);
    }
    timer = setTimeout(() => {
      fn.apply(this, args);
      isFirstCall = true;
      timer = null;
    }, delay);
  };
}

// 使用：提交按钮（第一次点击立即提交，防止用户连续双击）
const submitBtn = document.getElementById('submit') as HTMLButtonElement;
const handleSubmit = debounceImmediate(() => {
  console.log('✅ 表单已提交');
}, 3000);

submitBtn.addEventListener('click', handleSubmit);
// 连续点击 5 次：第一次立即执行，后 4 次被防抖合并
```


### 2.3 防抖在 React 中的应用（自定义 Hook）

```tsx
// ============================================
// React 防抖 Hook（推荐封装方式）
// ============================================
import { useCallback, useRef, useEffect } from 'react';

function useDebounce<T extends (...args: any[]) => any>(
  fn: T,
  delay: number
): T {
  const timerRef = useRef<NodeJS.Timeout | null>(null);

  // 每次 fn 或 delay 变化时，重新创建防抖函数
  const debouncedFn = useCallback(
    function(this: any, ...args: Parameters<T>) {
      if (timerRef.current) {
        clearTimeout(timerRef.current);
      }
      timerRef.current = setTimeout(() => {
        fn.apply(this, args);
        timerRef.current = null;
      }, delay);
    },
    [fn, delay]
  );

  // 组件卸载时清除定时器（防止内存泄漏）
  useEffect(() => {
    return () => {
      if (timerRef.current) {
        clearTimeout(timerRef.current);
      }
    };
  }, []);

  return debouncedFn as T;
}

// 在组件中使用：
function SearchInput() {
  const handleSearch = useDebounce((keyword: string) => {
    console.log('🔍 搜索:', keyword);
    // 调用 API
  }, 500);

  return (
    <input
      type="text"
      placeholder="搜索..."
      onChange={(e) => handleSearch(e.target.value)}
    />
  );
}
```

## 第三章：从零实现 —— 手写节流

### 3.1 基础节流（时间戳版）

```tsx
// ============================================
// 节流：用时间戳判断是否达到执行间隔
// ============================================
function throttle<T extends (...args: any[]) => any>(
  fn: T,
  interval: number
): (...args: Parameters<T>) => void {
  // ★ 闭包：记录上次执行的时间
  let lastTime = 0;

  return function(this: any, ...args: Parameters<T>) {
    const now = Date.now();
    // 当前时间 - 上次执行时间 >= 间隔 → 执行
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
    // 否则：不执行，忽略这次调用
  };
}

// 使用场景：滚动事件
const handleScroll = throttle(() => {
  console.log('📜 滚动位置:', window.scrollY);
}, 1000);

window.addEventListener('scroll', handleScroll);
// 无论滚动多快，每秒最多执行 1 次
```


### 3.2 节流（定时器版）—— 实现“第一次不执行，最后一次一定执行”

时间戳版有个特点：**第一次触发立即执行，最后一次触发如果没到间隔就不执行**。有时候我们需要“最后一次也执行”。

```tsx
// ============================================
// 节流（定时器版）：第一次延迟执行，最后一次一定执行
// ============================================
function throttleWithTrailing<T extends (...args: any[]) => any>(
  fn: T,
  interval: number
): (...args: Parameters<T>) => void {
  let timer: NodeJS.Timeout | null = null;
  let lastArgs: Parameters<T> | null = null;

  return function(this: any, ...args: Parameters<T>) {
    // 如果没有定时器 → 立即执行（首次触发）
    if (!timer) {
      fn.apply(this, args);
      // 设置定时器，interval 后检查是否有“遗漏”的执行
      timer = setTimeout(() => {
        timer = null;
        // 如果有“最后一次”的调用，执行它
        if (lastArgs) {
          fn.apply(this, lastArgs);
          lastArgs = null;
          // 重新设置定时器（形成循环）
          timer = setTimeout(() => {
            timer = null;
          }, interval);
        }
      }, interval);
    } else {
      // 如果有定时器 → 记录最新的参数（等定时器结束后执行）
      lastArgs = args;
    }
  };
}
```


### 3.3 节流在 React 中的应用

```tsx
// ============================================
// React 节流 Hook
// ============================================
function useThrottle<T extends (...args: any[]) => any>(
  fn: T,
  interval: number
): T {
  const lastTimeRef = useRef<number>(0);

  const throttledFn = useCallback(
    function(this: any, ...args: Parameters<T>) {
      const now = Date.now();
      if (now - lastTimeRef.current >= interval) {
        lastTimeRef.current = now;
        fn.apply(this, args);
      }
    },
    [fn, interval]
  );

  return throttledFn as T;
}

// 使用场景：滚动加载更多
function InfiniteScrollList() {
  const handleScroll = useThrottle(() => {
    const scrollTop = window.scrollY;
    const windowHeight = window.innerHeight;
    const documentHeight = document.documentElement.scrollHeight;

    // 滚动到底部时加载更多
    if (scrollTop + windowHeight >= documentHeight - 100) {
      console.log('📦 加载更多数据...');
      // 调用加载 API
    }
  }, 500);

  useEffect(() => {
    window.addEventListener('scroll', handleScroll);
    return () => window.removeEventListener('scroll', handleScroll);
  }, [handleScroll]);

  return <div>... 列表内容 ...</div>;
}
```

## 第四章：防抖 vs 节流 —— 什么时候用哪个？

### 4.1 决策树（别再纠结了！）

```
问：这个事件触发后，我需要的是“最终结果”还是“过程反馈”？

├─ 需要“最终结果”（只看最后一次）→ ✅ 用防抖
│   ├─ 搜索框输入（只看用户输入完的结果）
│   ├─ 窗口 resize（只看最终尺寸）
│   ├─ 表单提交（防止重复点击）
│   └─ 编辑器内容保存（自动保存草稿）
│
└─ 需要“过程反馈”（不断更新状态）→ ✅ 用节流
    ├─ 滚动加载更多（每滚一段距离加载一次）
    ├─ 鼠标移动跟踪（刷新位置信息）
    ├─ 游戏射击（限制射速）
    └─ 视频播放进度上报（每隔几秒上报一次）
```

### 4.2 对比速查表

| 维度 | 防抖（Debounce） | 节流（Throttle） |
| :--- | :--- | :--- |
| **核心思想** | “等你停下来再执行” | “固定频率执行” |
| **执行次数** | 连续触发只执行最后一次 | 按固定间隔执行 |
| **首次触发** | 延迟执行（除非立即执行版） | 立即执行 |
| **最后一次触发** | 一定执行 | 视实现方式（时间戳版不执行，定时器版执行） |
| **适用场景** | 搜索输入、resize、自动保存 | 滚动、鼠标移动、游戏 |
| **生活中的类比** | 等没人按电梯了再关门 | 电梯每 3 秒只能按一次 |

## 第五章：💣 血泪踩坑大全（价值 1000 个通宵）

### 💣 天坑 1：防抖/节流函数里的 `this` 丢失

**当年情景：**
我在 Vue 组件里用防抖，结果 `this` 变成了 `undefined`，组件方法调用失败。

```tsx
// ❌ 错误：this 指向丢失
const obj = {
  name: '张三',
  sayHi: function() {
    console.log('你好', this.name);
  }
};

const debouncedSayHi = debounce(obj.sayHi, 1000);
debouncedSayHi(); // ❌ this 指向 window/undefined，this.name 报错
```

**根源：** 防抖返回的新函数被调用时，`this` 失去了原来的上下文。

**解决方案：用 `apply` 或 `call` 绑定 this（我们之前代码已经正确处理了）**

```tsx
// ✅ 正确：在防抖内部用 fn.apply(this, args)
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args); // 关键！保留 this
    }, delay);
  };
}

// 使用：绑定 this
const obj = { name: '张三' };
obj.sayHi = debounce(function() { console.log(this.name); }, 1000);
obj.sayHi(); // '张三' ✅
```

### 💣 天坑 2：React 中防抖函数每次渲染都重新创建

**当年情景：**
我在 React 组件里定义了 `debounce(search, 500)`，每次输入都触发，但防抖完全不生效。

```tsx
// ❌ 错误：每次渲染都创建新的防抖函数
function Search() {
  const [keyword, setKeyword] = useState('');

  // 每次渲染都会创建新的 debouncedSearch！
  const debouncedSearch = debounce((kw: string) => {
    console.log('搜索:', kw);
  }, 500);

  return (
    <input
      value={keyword}
      onChange={(e) => {
        setKeyword(e.target.value);
        debouncedSearch(e.target.value); // 每次都是新的函数，防抖失效！
      }}
    />
  );
}
```

**根源：** React 每次渲染都重新执行组件函数，`debounce` 被重复调用，每次都创建新的定时器闭包。

**解决方案 1：用 `useCallback` 稳定防抖函数**

```tsx
// ✅ 用 useCallback 缓存防抖函数
function Search() {
  const [keyword, setKeyword] = useState('');

  const debouncedSearch = useCallback(
    debounce((kw: string) => {
      console.log('搜索:', kw);
    }, 500),
    [] // 空依赖：永远不重新创建
  );

  return (
    <input
      value={keyword}
      onChange={(e) => {
        setKeyword(e.target.value);
        debouncedSearch(e.target.value);
      }}
    />
  );
}
```

**解决方案 2：用 `useRef` 保存防抖函数**

```tsx
// ✅ 用 useRef 保存
function Search() {
  const [keyword, setKeyword] = useState('');
  const debouncedRef = useRef(
    debounce((kw: string) => { console.log('搜索:', kw); }, 500)
  );

  return (
    <input
      value={keyword}
      onChange={(e) => {
        setKeyword(e.target.value);
        debouncedRef.current(e.target.value);
      }}
    />
  );
}
```

### 💣 天坑 3：防抖/节流无法取消（导致内存泄漏）

**当年情景：**
用户快速切换到其他页面，但之前的防抖任务还在排队，执行时 `setState` 已经不存在了，报错。

**解决方案：添加 `cancel` 方法**

```tsx
// ✅ 带取消功能的防抖
function debounceWithCancel<T extends (...args: any[]) => any>(
  fn: T,
  delay: number
): {
  (...args: Parameters<T>): void;
  cancel: () => void;
} {
  let timer: NodeJS.Timeout | null = null;

  const debounced = function(this: any, ...args: Parameters<T>) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
      timer = null;
    }, delay);
  };

  // 添加 cancel 方法
  debounced.cancel = () => {
    if (timer) {
      clearTimeout(timer);
      timer = null;
    }
  };

  return debounced;
}

// React 中使用（组件卸载时取消）
function Search() {
  const debouncedSearch = useMemo(() => 
    debounceWithCancel((kw: string) => {
      console.log('搜索:', kw);
    }, 500),
    []
  );

  useEffect(() => {
    return () => {
      debouncedSearch.cancel(); // 组件卸载时取消待执行任务
    };
  }, [debouncedSearch]);

  return <input onChange={(e) => debouncedSearch(e.target.value)} />;
}
```


### 💣 天坑 4：节流时间戳版导致“最后一次不执行”

**当年情景：**
滚动加载更多，用时间戳版节流，用户滚到最后时刚好“差 100ms 到间隔”，加载没触发，用户以为没有更多数据了。

**根源：** 时间戳版节流只在“达到间隔”时执行，最后一次触发如果没到间隔就被忽略了。

**解决方案：用定时器版节流（见 3.2 节），或用“leading + trailing”组合版**

```tsx
// ✅ 组合版节流：第一次执行 + 最后一次也执行
function throttleLeadingTrailing<T extends (...args: any[]) => any>(
  fn: T,
  interval: number
): (...args: Parameters<T>) => void {
  let timer: NodeJS.Timeout | null = null;
  let lastArgs: Parameters<T> | null = null;

  return function(this: any, ...args: Parameters<T>) {
    if (!timer) {
      // 第一次：立即执行
      fn.apply(this, args);
      timer = setTimeout(() => {
        timer = null;
        // 如果有“遗漏”的调用，执行最后一次
        if (lastArgs) {
          fn.apply(this, lastArgs);
          lastArgs = null;
        }
      }, interval);
    } else {
      // 持续触发：记录最新的参数
      lastArgs = args;
    }
  };
}
```


### 💣 天坑 5：防抖延迟太长导致“手感迟钝”

**当年情景：**
搜索框加了 500ms 防抖，用户打字时感觉“迟钝”，体验很差。

**根源：** 用户每输入一个字母，都要等 500ms 才看到搜索建议，视觉反馈滞后。

**解决方案：使用“立即执行版”防抖（首字立即搜索）**

```tsx
// ✅ 第一次输入立即执行，后续输入防抖
const debouncedSearch = debounceImmediate((kw: string) => {
  console.log('搜索:', kw);
}, 300);

// 用户输入 'a' → 立即搜索
// 用户输入 'ab'（200ms 后）→ 重置定时器
// 用户停止输入 → 300ms 后执行最后一次
```


### 💣 天坑 6：在 React 的 `onChange` 中直接使用闭包变量

**当年情景：**
我在 `onChange` 里调用了防抖函数，传入 `keyword`，但 `keyword` 总是旧值。

```tsx
// ❌ 错误：闭包陷阱
function Search() {
  const [keyword, setKeyword] = useState('');
  const debouncedSearch = useRef(
    debounce((kw: string) => {
      console.log('搜索:', kw);
    }, 500)
  ).current;

  return (
    <input
      value={keyword}
      onChange={(e) => {
        const value = e.target.value;
        setKeyword(value);
        // 这里传入 value，确保防抖函数拿到的是最新值
        debouncedSearch(value); // ✅ 传值调用，不用闭包
      }}
    />
  );
}
```

## 第六章：面试高频考点（准备用的）

### Q1：防抖和节流的区别是什么？（基础题）

- **防抖**：连续触发时只执行最后一次，适合搜索框输入。
- **节流**：连续触发时按固定频率执行，适合滚动事件。

### Q2：防抖/节流的实现原理是什么？（进阶题）

利用**闭包**保存 `timer`（防抖）或 `lastTime`（节流）变量，在闭包内部判断是否执行目标函数。

### Q3：`leading` 和 `trailing` 是什么意思？（高级题）

- **leading（开头）**：第一次触发时立即执行。
- **trailing（结尾）**：最后一次触发后延迟执行。

**组合模式：**
- `leading: true, trailing: false` → 只执行第一次
- `leading: false, trailing: true` → 只执行最后一次（标准防抖）
- `leading: true, trailing: true` → 第一次立即执行，最后一次也执行

### Q4：如何取消防抖/节流？（加分题）

给返回的函数添加 `cancel` 方法，清除内部的 `timer`。

## 写在最后（致当年那个迷茫的自己）

15 年前，我第一次看到“防抖”这个词时，脑子里全是问号。我以为它是什么复杂的算法，需要看很多书才能理解。

后来我发现，它不过就是 **“清掉之前的定时器，重新设一个”** 。就这么简单。

节流也不过就是 **“记住上次执行的时间，看是不是该执行了”** 。也这么简单。

**所有看似高深的技术，拆开来看，都是几个基本概念的组合。** 闭包 + 定时器 + 时间戳 = 防抖/节流。这就是一切。

**给你的三条“黄金法则”：**

1. **只要涉及到“高频触发 + 消耗性能”的场景，第一时间想到防抖和节流。** 这个条件反射能让你少写很多低效代码。
2. **防抖解决“最后一次”，节流解决“频率限制”。** 记不住就想想电梯关门（防抖）和电梯限行（节流）。
3. **在 React 中用防抖/节流，永远用 `useCallback` 或 `useRef` 来稳定函数引用。** 这是 React 专属坑，切记。

现在，去给你的项目加上防抖和节流吧。你会发现，性能问题解决了一大半。
